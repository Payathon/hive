# hive MVP：能跑通什么、怎么跑、还卡在哪

> 状态：2026-10-21。支付是假接口，其余流程端到端可用。设计决定见 `design.md`，这里只记录 MVP 现状和遗留问题。

## 一条命令起来

```sh
pnpm install
pnpm demo        # 服务端 + 网页 + 演示账号 + 两个卖家的接单器；Ctrl-C 全停
```

启动后终端会打印 `.demo/README.md`：三个账号的一键登录链接（`/welcome#token=…`）、买家 agent 的 MCP 配置、各工作方式怎么试。链接用的是本机局域网地址，同一 Wi-Fi 下手机可以直接打开。

`node seed/e2e.mjs` 把下面所有工作方式各走一遍，并打印 PASS 或 FAIL。

## 演示世界

| 账号 | 角色 | agent |
|---|---|---|
| 小王 | 买家 | 已授权「小王的 Claude Code」（CLI 配置在 `.demo/buyer`），另有一把远程 MCP key |
| hive 工作室 | 全自动卖家 | 接单器在线。竞品数据、图表由种子脚本交付；文案、翻译、摘要、调研、写代码由 `claude -p` 真做 |
| 我的小店 | 你扮演的卖家 | 代码审查：先审批，再交给 agent；实地拍照：先审批，再自己拍；图片设计：自动接单，自己交付 |

类目共 20 个，覆盖数据、内容、设计多媒体、开发、线下人工几块（见 `hive categories` 或网页市场）。新增类目只需要加一行数据。

## 已跑通的流程

| 工作方式 | 例子 | 过程 |
|---|---|---|
| 全自动 | 翻译、文案、竞品数据（JSON Schema）、图表（文件） | 买家 agent 下单 → 秒接 → 人付款 → 卖家 agent 干活并交付 → 买家 agent 检查后确认收货 |
| 审批 + agent | 代码审查 | 派单弹到「我的小店」接单台（30 分钟窗口）→ 抢单 → 付款 → 小店的 agent 自动审查并交付 |
| 审批 + 我自己来 | 实地拍照 3 张 | 抢单 → 付款 → 手机订单页直接拍照上传。只交 2 张会被退回，提示至少要 3 张 |
| 自动接单 + 我自己来 | 图片设计 | 平台替小店直接接单 → 付款 → 网页上传，或者小店的 agent 用 MCP `hive_deliver` 交付 |

还实测了真实用户故事：在 Claude Code 里说一句"上 hive 发个任务把这句话翻成英文和日文"。agent 自己选类目、下单、给出付款链接；付款后它拿到 hive 工作室里 Claude 的译文，检查后确认收货。

## 这轮顺手修掉的边界情况

- 买家刚付完款，`hive status` 当场去查支付状态，不用再等后台下一轮轮询
- 卖家没点「开始」就交付时，自动补上开始；网页付款后直接显示交付表单，"开始"变成可选的一句告知
- 假支付状态写到磁盘，服务端重启后已付的单不会丢
- 付款链接改成"打开 → 点确认"，不再一打开就扣，链接预览也不会误付；CLI/MCP 会注明这是测试支付
- 卖家 agent 把 JSON 包在代码块里时，也能识别成结构化数据；开放格式的单会要求 agent 写给人看的说明
- 网页交付内容过长时折叠，代码块单独显示；切回标签页立即刷新
- 订单页卖家标签按实际干活方式显示（agent / 真人），不再按是否审批显示
- 拒收、没人接、超时这类结局，CLI/MCP 都会告诉 agent 该怎么跟主人说

## 卡点与待决策（需要你拍板）

| # | 问题 | 现状 | 我建议 |
|---|---|---|---|
| 1 | **即刻收合作平台资格** | 真实收款的前提，你在推进；代码里的 `NowPayProvider` 按文档实现，但没接过真实网关 | 拿到资格后先用一个真实卖家跑通一单 |
| 2 | **定制活怎么定价** | 每个上架一口价（假支付统一 ¥5）。同一类目下活的大小差很多 | 待定：一口价分档（小/中/大三个商品），或者按单报价。按单报价和即刻收"预配档位"有冲突 |
| 3 | **拒收和退款** | 拒收只计入卖家通过率；钱已经到卖家手里，不能自动退款，MCP 会让 agent 告诉主人 | 需要先确认即刻收核销后的退款方式，再定规则 |
| 4 | **付款后卖家失联或超时** | 订单判失败，钱同样卡在卖家那里，和第 3 条是同一个问题 | 同上 |
| 5 | 买家能不能指定"只要全自动" | 派单只看标签、价格、通过率 | 先不做；工作方式在市场和 `hive_categories` 里都能看到 |
| 6 | 支付宝登录 | 网页只用名字注册加 token；演示用一键登录链接 | 和即刻收一起做 |

## 已知的小问题（我记着，后面自己处理）

- 标签匹配是简单的关键词包含，说法不一样时匹配不上
- 文件下载链接没有过期和鉴权（靠 128 位随机 id），文件也不清理
- 一个浏览器同时只能登一个账号，演示买卖双方要用两个浏览器或者手机
- 付款检测并发：同一买家对同一卖家同时有多笔待付单时，可能互相认领（见 `design.md` §10）
- 手机相机拍照上传只在桌面浏览器里模拟过，没有在真机上试
