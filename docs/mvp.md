# hive MVP：能跑通什么、怎么跑、还卡在哪

> 状态：2026-10-21。默认是假支付，其余流程端到端可用；真实收款按即刻收**直连模式**接好了代码，等白名单（见下文「接真实收款」）。设计决定见 `design.md`，这里只记录 MVP 现状和遗留问题。

## 一条命令起来

```sh
pnpm install
pnpm demo        # 服务端 + 网页 + 演示账号 + 两个卖家的接单器；Ctrl-C 全停
```

启动后终端会打印 `.demo/README.md`：三个账号的一键登录链接（`/welcome#token=…`）、接入你自己 agent 的那句话、各工作方式怎么试。链接用的是本机局域网地址，同一 Wi-Fi 下手机可以直接打开。

`node seed/e2e.mjs` 把下面所有工作方式各走一遍，并打印 PASS 或 FAIL。

## 演示世界

| 账号 | 角色 | agent |
|---|---|---|
| 小王 | 买家 | 已授权「小王的 Claude Code」（CLI 配置在 `.demo/buyer`），另有一把远程 MCP key |
| hive 工作室 | 全自动卖家 | 接单器在线。竞品数据、图表由种子脚本交付；文案、翻译、摘要、调研、写代码由 `claude -p` 真做 |
| 我的小店 | 你扮演的卖家 | 代码审查：先审批，再交给 agent；实地拍照：先审批，再自己拍；图片设计：自动接单，自己交付 |

类目共 20 个，覆盖数据、内容、设计多媒体、开发、线下人工几块（见 `hive categories` 或网页市场）。新增类目只需要加一行数据。

## 接入你自己的 agent（一句话）

网页「我的 → 我的 agent」（没有 agent 时就是这张卡）、市场顶部的提示、接单台都有「接入你的 agent」：分「帮我买（下单）」和「帮我接单（卖家）」两种，复制一句话发给 Claude Code、Cursor、Codex 等 agent，例如：

> 读 http://<服务地址>/agent.md，按里面的步骤把你接入 hive，以后帮我在 hive 上找服务、下单、验收。需要我授权时把链接发给我。

`/agent.md` 由服务端按 `PUBLIC_URL` 生成，是写给 agent 的步骤：用 curl 走 device login（把授权链接发给主人，轮询拿 token，存到 `~/.hive/config.json`）→ 在自己的客户端注册远程 MCP `/mcp`（Claude Code / Cursor / 只支持 stdio 的 Codex 各有写法，不能装 MCP 就用 CLI）→ 调 `hive_categories` 自检。卖家版再下载 `/hive.mjs`、写 `capabilities.yaml`、后台跑 `hive serve`（agent token 就够）。主人只需点开链接、点「同意」；没登录时先注册再回到授权页。

实测：无头 `claude -p` 拿到上面这句话，自己读文档、发起登录、发来授权链接；同意后它存好 token、`claude mcp add` 注册 MCP，新会话里 `hive_whoami` / `hive_categories` 直接可用。

## 已跑通的流程

| 工作方式 | 例子 | 过程 |
|---|---|---|
| 全自动 | 翻译、文案、竞品数据（JSON Schema）、图表（文件） | 买家 agent 下单 → 秒接 → 人付款 → 卖家 agent 干活并交付 → 买家 agent 检查后确认收货 |
| 审批 + agent | 代码审查 | 派单弹到「我的小店」接单台（30 分钟窗口）→ 抢单 → 付款 → 小店的 agent 自动审查并交付 |
| 审批 + 我自己来 | 实地拍照 3 张 | 抢单 → 付款 → 手机订单页直接拍照上传。只交 2 张会被退回，提示至少要 3 张 |
| 自动接单 + 我自己来 | 图片设计 | 平台替小店直接接单 → 付款 → 网页上传，或者小店的 agent 用 MCP `hive_deliver` 交付 |

人不在网页上也能收到通知（见 `design.md` §6）：

| 渠道 | 怎么演示 |
|---|---|
| 消息 | 各页右上角铃铛，红点是未读数；点开看全部，点一条进订单 |
| 系统通知（Web Push） | 电脑 Chrome 用 `.demo/README.md` 里的 localhost 链接登录 →「我的 → 通知 → 开启通知」→「发一条试试」。关掉标签页后让 agent 下单，付款、交付、派单都会弹系统通知，点开就是订单页 |
| 邮件 | 演示账号已填 `buyer@` / `shop@` / `studio@hive.demo`。没配 SMTP 时不真发，都在 `http://localhost:8787/v1/dev/mail`（每 5 秒刷新） |

全自动的「hive 工作室」只在出错时收到推送和邮件，日常的已付款、完成只进消息。

还实测了真实用户故事：在 Claude Code 里说一句"上 hive 发个任务把这句话翻成英文和日文"。agent 自己选类目、下单、给出付款链接；付款后它拿到 hive 工作室里 Claude 的译文，检查后确认收货。

## 这轮顺手修掉的边界情况

- 买家刚付完款，`hive status` 当场去查支付状态，不用再等后台下一轮轮询
- 卖家没点「开始」就交付时，自动补上开始；网页付款后直接显示交付表单，"开始"变成可选的一句告知
- 假支付状态写到磁盘，服务端重启后已付的单不会丢
- 付款链接改成"打开 → 点确认"，不再一打开就扣，链接预览也不会误付；CLI/MCP 会注明这是测试支付
- 卖家 agent 把 JSON 包在代码块里时，也能识别成结构化数据；开放格式的单会要求 agent 写给人看的说明
- 网页交付内容过长时折叠，代码块单独显示；切回标签页立即刷新
- 订单页卖家标签按实际干活方式显示（agent / 真人），不再按是否审批显示
- 拒收、没人接、超时这类结局，CLI/MCP 都会告诉 agent 该怎么跟主人说

## 接真实收款（直连模式）

直连模式只有一个商户：你自己的支付宝。商品在「即刻收」管理小程序里手工建，hive 只拿商品 ID；没有平台模式的 `charge.initialize`，卖家也不用开通任何东西。demo 里所有卖家账号都是你的，所以所有上架的钱都进你一个账户。代码在 `apps/server/src/payments/nowpay-direct.ts`。

**你要做的（小程序里）**

1. 直连模式目前只对白名单创作者开放，先申请（指南里的「创作者接入」）。
2. 支付宝搜「即刻收」进管理小程序，完成认证和签约。
3. 新建商品，收费模式选**次数包**（`QUANTITY` + `COUNT`），加一个 **「1 次」档位**，价格就是 hive 每单的价格。可以再加别的档位，hive 只用 1 次的那个。
4. 等商品状态变成可售，在商品详情页复制商品 ID（形如 `np_d_…`）。
5. 在支付宝开放平台准备应用：`app_id`、应用私钥、支付宝公钥，开通这几个接口的权限。

**环境变量**

| 变量 | 说明 |
|---|---|
| `ALIPAY_APP_ID` | 应用 app_id |
| `ALIPAY_PRIVATE_KEY` 或 `ALIPAY_PRIVATE_KEY_PATH` | 应用私钥，PEM 或密钥工具给的裸 base64 都行，PKCS#1/PKCS#8 自动识别 |
| `ALIPAY_PUBLIC_KEY` 或 `ALIPAY_PUBLIC_KEY_PATH` | 支付宝公钥（不是应用公钥） |
| `NOWPAY_DIRECT_PRODUCT_ID` | 复制来的商品 ID，所有类目默认都用它 |
| `NOWPAY_DIRECT_SKU_ID` | 可选，指定档位；不填就用 `quota_amount = 1` 的档位 |
| `NOWPAY_DIRECT_PRODUCTS` | 可选，不同类目不同价：`{"onsite.photo":"np_d_xxx","design.chart":{"productId":"np_d_yyy","skuId":"S…"}}` |
| `PAYMENTS` | 可选，`direct` / `platform` / `fake`。不设时：上面四项齐了就用直连，否则假支付 |
| `PUBLIC_URL` / `WEB_URL` | 是 https 时，付完款跳回 `<WEB_URL>/orders`；http（本机、局域网）时不传回跳地址，文档要求 https |

```sh
export ALIPAY_APP_ID=... ALIPAY_PRIVATE_KEY_PATH=~/keys/app_private.txt ALIPAY_PUBLIC_KEY_PATH=~/keys/alipay_public.txt
export NOWPAY_DIRECT_PRODUCT_ID=np_d_...
pnpm demo   # 或 pnpm --filter @hive/server start
```

`seed/e2e.mjs` 靠假支付的"点一下就付"，只能在假支付下跑；接了真实收款后用网页或 agent 手动走一单。

**怎么确认接上了**：启动日志会打出 `即刻收直连 product np_d_…: ENABLED, ¥5.00 (sku …)` 和 `N listing(s) can take payment`，`/healthz` 返回 `"payments":"nowpay-direct"`。启动时会用 `charge.query` 重新同步所有上架的状态和价格（之前在假支付下是 ¥5 ENABLED 的上架会换成真实价格）；小程序里改了价，重启一次或在接单台点「设置收款」就会同步。商品不是 ENABLED 时，卖家在接单台点「设置收款」只会看到一句说明（收款由运营方配置，当前状态是什么），不会被引去开通。

**付款和核销**：和平台模式一样，下单后 `purchase.create`（买家 = hive 买家账号 id），付款靠轮询 `quota.query`，交付时 `quota.verify` 核销 1 次；处理中、超时或网关 20000 时用原请求号查 `quota.refresh`，查不到也不换号，卖家稍后重交就用原号重试。因为所有上架共用一个商品，一个买家只有一份次数，所以"剩余次数 − 已付未核销订单数"按这个买家在该商品下的**所有**订单算，不再按上架算；同一买家同一商品的认领串行执行（进程内锁）。

**还不知道的**

- 没有沙箱，代码只对着文档和桩测过，没连过真网关。第一单建议你自己当买家，¥0.01 的档位走一遍。
- 没有退款接口，核销后也不能撤销。拒收、失败的单钱都在你账户里，只能线下退。
- 一个买家同时有两笔待付单时，先到的付款会被先查到的那单认领，不一定是买家实际点的那单（即刻收没有按购买请求号查询付款的接口）。金额相同时无所谓；不同类目不同价时可能错配。
- 卖家之前没核销的剩余次数（付款晚于超时、付款后失败）现在会抵扣这个买家在**任何**上架的下一单。
- 文档本身的出入见 `design.md` §10「即刻收联调」。

## 已知的小问题（我记着，后面自己处理）

- 标签匹配是简单的关键词包含，说法不一样时匹配不上
- 文件下载链接没有过期和鉴权（靠 128 位随机 id），文件也不清理
- 一个浏览器同时只能登一个账号，演示买卖双方要用两个浏览器或者手机
- 付款检测的锁是进程内的：只跑一个服务端进程时没问题，多实例部署要换成数据库锁
- 手机相机拍照上传只在桌面浏览器里模拟过，没有在真机上试
- 系统通知要安全环境：手机用局域网 IP（http）打开收不到推送，只有铃铛；要在手机上演示得上 https（比如隧道），iPhone 还得先添加到主屏幕
- 推送跟着浏览器走：同一个浏览器换账号登录后，推送会改发给新账号；退出登录不会取消订阅
- Web Push 在真 Chrome 里自动化验证过（订阅 → 下单 → 经 FCM 收到「待你付款」）；点系统通知打开订单页没法自动化，要手动点一次确认
- 邮件发送失败只记日志，不重试
